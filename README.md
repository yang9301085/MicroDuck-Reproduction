# MicroDuck-Reproduction
复刻 MicroDuck

## 项目硬件与当前联调基线

本项目使用 **飞特 HD-1910-C001 舵机**和 **Lygion（灵影）TTL Adapter (A)**，它们是 MicroDuck 的项目硬件，不只是临时学习器材。

当前开发与联调平台为 **ATK-DLRK3568**，通信链路为：

`RK3568 UART9 → TTL Adapter (A) → HD-1910-C001`

这描述当前联调平台，不限定最终机器人的主控架构。根据[用户进度记录](https://chatgpt.com/space/page_d351a251b2088191ac832d9774d86445)，当前串口为 `/dev/ttyS9`，请求配置为 **1000000 bps、8N1、无流控**；这些是既有记录，并非本次新增实测或对实际线路速率的测量。

Python 标准库（`os/select/termios/time`）已收到有效舵机应答，完成位置读取与一次小角度动作：位置 2080 → 目标 2112 → 反馈 2111，返回 `ERROR 00`。大角度 1024 → 3072 测试中，第二目标动作曾返回 `ERROR 01`；按通用协议表示电压异常，但欠压、过压及动态供电原因尚未实测确认，不能将 DMA 回退中断直接视为故障根因。供电路径和 Adapter 实物版本仍待核实，此处不据此给出接电方案。

## C 学习课程与验证边界

- [Lesson00：Linux 用户态串口应用](Learning/ServoTTL/Lesson00-Serial/README.md)：学习打开、配置、二进制收发、超时和十六进制日志；使用已有内核串口接口，不重写 UART 驱动。
- [Lesson01：离线 PING 组包与校验](Learning/ServoTTL/Lesson01-Ping/README.md)：学习舵机协议层的请求、应答格式和校验和。

两课 C 代码目前仅在云端通过离线或伪终端（PTY）模拟测试，**尚未在 RK3568 实机验证**。Python 的实机成功不等于 C 实现已在板上通过；后续需核对已验证的串口配置与硬件规格，再将串口通信层与舵机协议层连接起来验证。
