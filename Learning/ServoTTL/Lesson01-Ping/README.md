# 第一课：离线理解 ID 1 的 PING

目标：看懂六个字节，使用 C 组包并验证校验和。本课不访问串口，不发送任何命令，也不是完整驱动。

依据：[飞特磁编码协议手册](../../../Docs/Servos/Feetech/Protocols/舵机协议手册-磁编码版本.pdf)第 2 页的帧格式、校验规则，以及第 3、4 页的 PING 示例。此链接路径以仓库目录结构为准。

## 逐字节拆解

以下数值均为十六进制。

| 偏移 | 请求 | 应答 | 含义 |
| --- | --- | --- | --- |
| 0、1 | FF FF | FF FF | 帧头，不参与校验和 |
| 2 | 01 | 01 | 舵机 ID 为 1 |
| 3 | 02 | 02 | Length = 参数数量 + 2；本例没有参数 |
| 4 | 01 | 00 | 请求是 PING 指令；应答是 ERROR 状态，00 表示无报错 |
| 5 | FB | FC | 校验和 |

Length 不是整个帧的长度：本例总长为 6。请求和应答的第 4 字节含义不同，不能把应答中的 00 当作指令。

请求：`01 + 02 + 01 = 04`，低八位取反：`~04 & FF = FB`。

应答：`01 + 02 + 00 = 03`，低八位取反：`~03 & FF = FC`。

因此请求为 `FF FF 01 02 01 FB`，无报错应答为 `FF FF 01 02 00 FC`。验证时可将 ID 到校验字节相加，检查低八位是否为 FF。

对熟悉 BIOS/UEFI 的工程师，这类似于按规范构建字节缓冲区；但这是飞特协议的取反校验，不能套用 ACPI 表的加和为零规则。C 中小整数参与运算会发生整数提升，所以代码用 unsigned 中间值并显式保留低八位。

## 文件与运行方法

- `ping.h`：两个练习函数的接口。
- `ping.c`：固定 ID 1 的 PING 组包；六字节帧的结构与校验检查。
- `test_ping.c`：独立手册向量、坏校验、坏帧头、错误长度、截断和空输入测试。

在云端环境运行：

```sh
cd /workspace/MicroDuck-Reproduction/Learning/ServoTTL/Lesson01-Ping
gcc -std=c11 -Wall -Wextra -Werror -pedantic ping.c test_ping.c -o /tmp/microduck-lesson01-ping-test
/tmp/microduck-lesson01-ping-test
```

可执行文件放在 `/tmp`，不会混进仓库。测试程序打印每项结果，有失败时返回非零退出码。先阅读测试中的固定向量，再对照实现。若想自行练习，可尝试独立重写这两个函数，保持测试不变。

校验通过仅说明该六字节帧满足本课检查规则，不证明它是本次请求的匹配应答，也不证明实体舵机正常。函数尚未检查 ID 匹配或解释 ERROR，更没有处理连续字节流。

## 本课边界

这是舵机协议层的离线练习。Linux 用户态串口配置、读写与超时，以及内核 UART 驱动均不在本课范围。

已知后续连接为 RK3568 板载 UART → 灵影 TTL Adapter，并使用独立电源。HD-1910-C001 的协议兼容性、型号控制表、接口电平与适配器规格仍须确认；本课的通用手册向量不能作为实机兼容性证据。云端没有实体串口访问，本课未做硬件测试。
