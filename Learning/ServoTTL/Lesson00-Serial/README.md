# Lesson00：先学 Linux 用户态串口应用

本课先建立一个可以打开串口、配置参数、发送二进制数据、带超时接收并打印日志的 C 应用。它不包含舵机命令或校验算法，也不访问 UART 寄存器。保留 Lesson01，等通信层参数得到实机确认后再接入。

## 三层边界

- UART 是串行收发硬件；TTL 描述电气接口相关特性，不是舵机报文格式。电平、电压、接线、收发方向控制不能由这个程序推断。
- Linux 内核驱动管理 UART 硬件，通过 TTY 设备节点提供接口。应用使用 `open`、`termios`、`read/write`、`poll`，通常无需重写内核 UART 驱动。
- 舵机协议决定发送哪些字节、如何识别回复。本课只搬运字节，不生成 PING。

已知将来的连接为 RK3568 板载 UART → 灵影 TTL Adapter → 舵机，另有独立电源。此前成功的 Python 脚本暂不在手边，真实设备路径、波特率、电气规格和方向控制方式仍待核对。当前不操作接线、电源或实体串口。

## 按什么顺序读

1. 先读 `main.c` 的 main：解析参数 → 打开 → 可选发送 → 接收一次 → 关闭。
2. 再看 `serial.h`：了解三个操作的返回值和调用约束。
3. 在 `serial.c` 看 `serial_open`：`O_NOCTTY` 不获取控制终端，`O_NONBLOCK` 配合 poll 防止读写无限阻塞；`cfmakeraw` 关闭行缓冲、回显和字符转换。
4. 看 `serial_write_all`：一次 write 可能只接收部分字节，所以循环推进偏移。
5. 看 `serial_read_some` 与 `wait_ready`：用单调时钟计算总期限，信号中断或暂不可用不会重新获得完整超时时间。
6. 最后运行模拟测试，对照 TX/RX 十六进制日志。

与 BIOS/UEFI 不同，这里的 fd 是内核提供的文件描述符，应用不直接操作 MMIO。二进制缓冲区必须携带长度，不能用 strlen 判断有效数据。

## 本课明确采用的配置

教学实现固定为 raw、8 数据位、无校验、1 停止位、无软/硬流控（8N1）。这不是对实际设备参数的确认；不符合已验证硬件配置时需要调整后才能用于板端。

波特率必须传入；支持 9600、19200、38400、57600、115200、230400、460800、921600、1000000。这里的支持仅表示可映射为 Linux termios 常量，不保证每款 UART 或适配器都支持。未实现任意波特率。

## 编译与纯模拟测试

需要 Linux、GCC、Python 3 标准库和系统 PTY 头文件；不需要 pyserial，也不安装新软件。在仓库根目录运行：

```sh
cd Learning/ServoTTL/Lesson00-Serial
gcc -std=c11 -Wall -Wextra -Werror -pedantic serial.c main.c -o /tmp/microduck-lesson00
python3 test_serial.py /tmp/microduck-lesson00
gcc -std=c11 -Wall -Wextra -Werror -pedantic serial.c test_api.c -lutil -o /tmp/microduck-lesson00-api-test
/tmp/microduck-lesson00-api-test
```

`test_serial.py` 自动创建 PTY master/slave。C 应用打开 slave；Python 在 master 上读取和写入模拟数据。模拟使用 115200 只是测试配置，不是建议的真实波特率。测试中的普通文件和不存在路径也由临时目录生成。

测试覆盖：

- 二进制收发，包含 00、FF、11、13、0A、0D、80；验证 raw 和波特率设置。
- 不提供发送参数时只接收，不主动发送字节。
- 接收超时、对端断开、不存在设备、普通文件不是 TTY。
- 非法数字、十六进制和缺少参数，在打开设备前拒绝。
- API 测试向无人读取的 PTY 写大缓冲区，验证堵塞时的发送总超时；再检查断开后的发送错误和非法 API 参数。

第一次使用占位 main 运行测试时，8 个测试方法失败（含参数子用例，共 13 个失败记录）；实现后预期 Python 显示 `Ran 8 tests ... OK`，API 测试显示 `4 checks, 0 failures`。这些结果仅证明软件模拟行为。

## 命令行如何理解

语法（尖括号是占位说明，不是可以直接执行的设备配置）：

```text
microduck-lesson00 <DEVICE> <BAUD> <TIMEOUT_MS> <MAX_RX> ["HH HH ..."]
```

所有前四项必填，没有默认设备和默认波特率。超时为 1..60000 毫秒，最大单次接收为 1..4096 字节。最后的发送参数可省略；省略就不调用 write。提供时，每个字节必须为两个十六进制字符，字节以空白分隔，最多 4096 字节。没有参数运行只打印用法，不打开任何设备。

`READY` 表示打开及配置成功，不表示对端在线。`TX` 表示全部字节已交给内核；`RX` 是本次 read 得到的字节。退出码 0 表示读到数据；2 表示接收超时；1 表示参数、打开、收发或关闭错误。发送超时属于错误，打印原因并返回 1，可能已经发出部分数据，不自动重发。

## 必须知道的限制

- 一次 read 只返回当前可得的一段数据，可能只是半包；MAX_RX 是上限，不是等待凑齐的长度。程序收到第一段就退出，本课没有完整帧接收器。
- 发送和接收分别有自己的总超时；不是整个进程共用一个期限。打开、配置与关闭不受 poll 超时控制。
- write 成功不等于最后一个停止位已经到达线路。本课未调用可能阻塞的 tcdrain，也未实现 TTL Adapter 收发方向切换。
- 打开和配置真实串口可能影响控制线；“不提供发送参数”只保证不写数据，不代表接入硬件没有电气影响。本轮只使用 PTY。
- 不清空已有接收数据，不改设备权限，不保证独占设备；关闭后不恢复原 termios。以后上板前应确认无其他进程使用该串口。
- PTY 不模拟实际波特率传输时序、电平、线缆、方向切换或舵机兼容性；本轮没有任何实机验证。
